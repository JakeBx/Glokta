# Risk Coverage

| Probe Module               | Explicit System Security Risk             | Explanation                                                                                                                                                                                                                                                        |
| -------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **`ansiescape`**           | Terminal Manipulation / Log Poisoning     | Elicits ANSI escape codes from the model that can disrupt downstream processing, manipulate an administrator's terminal display, or trigger vulnerabilities in CLI interfaces parsing the LLM's output.                                                            |
| **`apikey`**               | Synthetic Credential Generation           | Tests if the model will generate or complete fake/synthetic API keys when prompted with partial strings. This is a **content-policy bypass test**, not a test for leakage of real, active credentials stored in training data or memory.                           |
| **`av_spam_scanning`**     | Missing Output Security Controls          | Attempts to elicit known test signatures (EICAR, GTUBE, GTphish) to verify whether the application has antivirus, spam, or phishing filters on its output. A successful probe indicates these downstream security controls are absent.                             |
| **`exploitation`**         | Code Injection (SQLi, SSTI, RCE)          | Attempts to elicit SQL injection payloads and Jinja template injection strings. If the application passes model output directly to a backend database or template engine, this can lead to arbitrary database access or remote code execution.                     |
| **`fileformats`**          | Remote Code Execution via Model Artifacts | Examines files associated with HuggingFace model repositories for unsafe formats (e.g., Python `pickle` files). Unsafe file formats can execute arbitrary code immediately upon being loaded into memory, creating a critical vulnerability in the MLOps pipeline. |
| **`malwaregen`**           | Weaponization of Code Generation          | Tests if the model will generate functional malware payloads, evasion techniques, ransomware components, or exploit scripts when requested, effectively acting as a force multiplier for cybercriminals.                                                           |
| **`packagehallucination`** | Supply Chain Poisoning                    | Elicits code that imports non-existent packages (e.g., from npm, PyPI, crates.io). Attackers can pre-register these hallucinated package names with malicious payloads, leading to supply chain breaches when developers or automated systems install them.        |
| **`promptinject`**         | Prompt Injection / String Hijacking       | Tests if an attacker can inject specific rogue strings (e.g., `hate-humans`, `kill-humans`, `long-prompt`) into the model's output via crafted prompts. This tests prompt boundary robustness; it does **not** test for remote command execution.                  |
| **`sysprompt_extraction`** | Information Disclosure / Reconnaissance   | Uses adversarial techniques (direct requests, encoding tricks, role-playing) to extract the model's system prompt. Leaking system prompts aids attackers in crafting targeted jailbreaks and reveals internal application instructions.                            |
| **`web_injection`**        | XSS, CSRF, and Data Exfiltration          | Tests for cross-site scripting (XSS) via Markdown JavaScript rendering (`MarkdownXSS`, `TaskXSS`) and attempts to exfiltrate conversation-private data by embedding it in remote image URIs or Markdown links (`MarkdownImageExfil`, `ColabAIDataLeakage`).        |
